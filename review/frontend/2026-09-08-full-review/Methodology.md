# Methodology

The review used static inspection of the React/Vite frontend: route registration and role gating (`src/App.jsx`), the API client and token-refresh interceptor (`src/lib/api.js`), auth/theme context, candidate/recruiter/admin components and pages, the shared `components/ui/` and `components/ui/shadcn/` primitives, `src/styles/global.css` tokens and breakpoints, and the Vitest suite under `tests/`. `redesign-notes/clear-precise/plan.md` was read for design history and the documented 390px/1440px/320px/768px acceptance targets.

Commands actually run on 2026-09-08: `npm run build` (passed, `vite build` produced `dist/`), `npx vitest run` (7 files, 22 tests, all passed), and `npm audit --omit=dev --json` (7 production-tree vulnerabilities: 5 high, 2 moderate — see `Concerns/react-router-dependency-vulnerabilities.md` for which of those actually ship to the browser versus being build-tooling-only). A parallel `npm audit --json` (including devDependencies) was also inspected for comparison but is not the primary basis for severity, matching the backend review's use of `--omit=dev`.

Color-contrast ratios for the Graphite palette were computed by hand (WCAG relative-luminance formula) for the most-used text/background pairs in `src/styles/global.css`, not measured with an automated tool. No live browser session, authenticated account, or backend was used — this is a source-level review, consistent with the backend and ai-service reviews it accompanies. Severity follows the same convention: High requires prompt remediation before public deployment; Medium requires an owner and a decision before public deployment; Low/Info is maintainability or preservation-worthy.
